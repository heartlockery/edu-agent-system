## 2. 我学到的三件事

### 2.1 LangChain：它不是"大模型"，是"把大模型接进工程"的粘合层

最直接的收获：模型调用要从"写死一个 API 请求"变成可配置、可替换、可降级的能力。

- 同一份代码，改环境变量就能换模型/换厂商（`ChatOpenAI(model=..., base_url=...)`）；
- 提示词集中管理，人格和规则不散落在业务代码里；
- 模型不可用时要能降级，而不是整个系统挂掉。

### 2.2 LangGraph：把"一次问答"变成"可控的流程"

大模型最麻烦的是不确定。LangGraph 给我的价值是把不确定的部分（选哪个工具、说什么）关进节点里，
而把确定的部分（先规划、再执行、最后作答、最多两轮）用图固定下来：

```
intake ──> planner ──(有工具调用)──> executor ──> responder ──> END
              └────(无需工具)────────────────────> responder ──> END
```

### 2.3 Python 异步：真正要解决的是"别让一个慢东西堵住所有人"

我先纠正自己一个误区：这里的"多线程"不是开线程抢锁跑业务，而是：

- **协程（asyncio）**处理网络/数据库这类 IO 等待，一个进程就能同时服务几十个请求；
- **线程池（`asyncio.to_thread`）**只用来卸载会阻塞事件循环的同步库（比如 openpyxl 解析 Excel）；
- 阻塞操作一旦跑在事件循环里，整个服务会"卡住所有人"，这才是异步真正要防的事故。

## 3. LangChain 实践中遇到的坑（真实报错 + 我的处理）

### 3.1 不同厂商的 Function Calling 格式不统一

**现象**：换一个模型供应商，`bind_tools` 传进去的工具描述不生效或直接报错，工具永远不被调用。
**原因**：OpenAI、DeepSeek、通义对 function calling 的字段与约束并不完全一致，兼容层靠不住。
**处理**：不依赖厂商协议，改成"让模型输出一段 JSON 计划，我自己解析"：

```python
# app/ai/prompts.py
PLANNER_TEMPLATE = """只输出 JSON：
{{"tool_calls": [{{"tool": "工具名", "args": {{"参数": "值"}}}}]}}
【可用工具】{tools}
【用户问题】{question}"""
```

好处：任何能返回文本的模型都能用；坏处：模型可能不听话，所以必须有容错解析（见 3.2）。

### 3.2 模型把 JSON 包在 Markdown 代码块里，json.loads 直接崩

**现象**：`json.decoder.JSONDecodeError`，日志里看到模型返回的内容外面包了三反引号代码块。
**原因**：模型习惯性加代码块标记。
**处理**：先剥离代码块再取第一个大括号区间（app/ai/llm.py `_extract_json`）：

```python
FENCE = chr(96) * 3          # 避免源码里直接写三个反引号
if text.startswith(FENCE) or text.endswith(FENCE):
    text = text.replace(FENCE + "json", "").replace(FENCE, "").strip()
start, end = text.find("{"), text.rfind("}")
return json.loads(text[start:end + 1]) if start != -1 and end != -1 else {}
```

### 3.3 提示词里写 JSON 示例，和 Python 的 str.format 打架

**现象**：`KeyError: '"tool_calls"'`。
**原因**：`format` 把示例里的 JSON 花括号当成占位符。
**处理**：示例里的花括号写成双花括号 `{{ }}`（上面 3.1 的模板就是处理后的结果）。

### 3.4 Embedding 接口 404：不是所有模型都提供向量服务

**现象**：服务器日志 `POST https://api.deepseek.com/v1/embeddings "HTTP/1.1" 404`，启动被拖了 2 分钟。
**原因**：我拿聊天模型的 Key 去调 embeddings，DeepSeek 根本没有这个接口，等它超时才回退。
**处理**：
1. 加开关 `EMBEDDING_PROVIDER`，默认 `offline`，只有显式配了专用 Key 才走向量；
2. 调用加 12 秒超时，失败立即回退到 TF-IDF；
3. 启动不再同步等待知识库（见 5.3）。

### 3.5 模型挂了，系统不能跟着挂

**处理**：写了一个"离线规则引擎" `app/ai/mock_llm.py`：没 Key 或调用异常时，用关键词把中文问题映射成工具调用，
再把工具结果拼成人话。它同时是**测试环境**（不花钱、不依赖网络）和**线上兜底**（模型超时的那几秒）。

### 3.6 超时与重试

`ChatOpenAI(timeout=30, max_retries=1)`。教训：一次网络抖动不该让用户等 60 秒，宁可快速失败再兜底。

## 4. LangGraph 实践中遇到的坑

### 4.1 节点函数签名告警

**现象**：`UserWarning: The 'config' parameter should be typed as 'RunnableConfig' or 'RunnableConfig | None', not 'dict'`。
**处理**：把节点参数标注成 `RunnableConfig`，并用 `config["configurable"]` 取自定义内容。

### 4.2 数据库会话不能放进 state

**现象**：想当然把 `AsyncSession` 塞进图状态，结果 checkpointer 序列化失败，多轮直接断。
**原因**：state 会被 MemorySaver 持久化，而连接对象不可序列化。
**处理**：state 只放纯数据（问题、计划、结果、历史），会话和登录态通过运行配置传：

```python
config = {"configurable": {"thread_id": tid, "db": db, "ctx": ctx}}
out = await agent_graph.ainvoke({"role": role, "question": question}, config=config)
```

### 4.3 thread_id 设计不对会"串话"

**处理**：`thread_id = 角色:账号:会话ID`。少了账号，A 同学会看到 B 同学的上下文；少了角色，学生和老师会混在一起。

### 4.4 多轮追问答非所问（真实体验问题）

**现象**：先问"我上学期高数多少分"，再问"那英语呢"，系统把上一条答案又复述一遍。
**原因**：规划器只拿到对话文字，看不到"上一轮到底查到了什么"。
**处理**：把上一轮工具结果摘要一并注入规划器（app/ai/graph.py `planner_node`）：

```python
prev = state.get("tool_results") or []
if prev:
    hint = "；".join(r["tool"] + " -> " + str(r.get("message", ""))[:60] for r in prev[-2:])
    history = history + "\n[上一轮工具结果] " + hint
```

修复后线上实测：「那英语呢」→ 正确查大学英语(一)；「帮我预约它的考试」→ 正确理解为英语并提示已预约过。

### 4.5 一个工具报错不能把整张图炸掉

**处理**：executor 节点里逐个工具 try/except，把失败变成一条 `{ok: False, message: ...}` 结果继续往下走，
由 responder 告诉用户"这一步没成功"。用户的对话不会因为一个参数写错而中断。

### 4.6 条件边：没工具就别绕路

```python
graph.add_conditional_edges("planner", lambda s: "executor" if s.get("plan") else "responder",
                            {"executor": "executor", "responder": "responder"})
```

## 5. Python 异步实践中遇到的坑

### 5.1 `'coroutine' object has no attribute 'order_by'`（最典型的一个）

**现象**：教师"收件箱"接口 500。
**原因**：括号位置错，`await` 作用在了错误的表达式上：

```python
# 错：先对 db.execute(...) 取 order_by，再 await 一个 coroutine
rows = (await db.execute(select(Message).where(...)).order_by(Message.id.desc())).scalars().all()

# 对：order_by 属于 SQL 语句，await 只包住 execute
rows = (await db.execute(
    select(Message).where(Message.receiver_id == sno).order_by(Message.id.desc()))).scalars().all()
```

这就是异步编程最容易犯的错：**"忘了 await"和"await 放错位置"是两种不同的 bug**，后者不会报 await 缺失，
而是报"coroutine 没有这个方法"，很绕。

### 5.2 `ImportError: The SQLAlchemy asyncio module requires that the Python 'greenlet' library is installed`

**原因**：SQLAlchemy 2.0 的异步依赖 greenlet，requirements 里写了 sqlalchemy 但没显式写 greenlet。
**处理**：requirements 补 `greenlet`；换成 PostgreSQL 还要 `asyncpg`（否则 `ModuleNotFoundError: No module named 'asyncpg'`）。

### 5.3 在 lifespan 里 await 网络请求 = 服务迟迟不监听端口

**现象**：部署完浏览器报 `ERR_CONNECTION_REFUSED`，但进程其实活着。
**原因**：启动钩子里同步等待知识库向量化（见 3.4），2 分钟内端口没起来。
**处理**：预热改成后台任务，启动立刻返回：

```python
asyncio.create_task(_warm_kb())      # 不阻塞启动，首次提问时也会自动加载
```

效果：启动从 2 分钟变成 **1 秒内**，systemctl restart 后立即 200。

### 5.4 同步库阻塞事件循环（openpyxl 解析 Excel）

**原因**：`load_workbook` 是纯同步 CPU/IO 混合操作，直接调用会把整个事件循环卡住，其他请求排队。
**处理**：丢进线程池（app/services/grades.py）：

```python
return await asyncio.to_thread(parse_grade_workbook, path)
```

### 5.5 超时控制：asyncio.wait_for

```python
await asyncio.wait_for(self._build_online(), timeout=12)
```
任何"外部依赖"都必须有超时，否则就是 5.3 那种事故。

### 5.6 关于"多线程"的澄清（老师可能会问）

- Web 服务层面用的是**协程**，不是每个请求一个线程；
- **线程池**只用于卸载阻塞调用（Excel 解析、同步文件 IO）；
- 压测证明并发能力：服务器本机 30 并发 × 5 轮 = 150 次请求，**0 失败**，平均 67ms、P95 118ms；
  公网同样 90 次 **0 失败**（受 1Mbps 带宽限制，平均 261ms）。

## 6. 三个技术怎么协同（一次对话的完整链路）

```
浏览器输入"我上学期高数多少分"
   │  POST /api/chat（带登录令牌）
   ▼
FastAPI 异步路由 ── 查学生/班级上下文（asyncpg 异步查询）
   │
   ▼
LangGraph intake  ── 把问题写进历史
   │
   ▼
planner（LangChain 调模型）── 输出 JSON 计划：
     {"tool":"query_grades","args":{"course_name":"高等数学A(上)"}}
   │
   ▼
executor ── 真实查数据库（异步），失败也只记一条错误结果
   │
   ▼
responder（LangChain 再调一次模型）── 润色成"同学，查到啦～65.2 分…"
   │
   ▼
返回答案 + 工具轨迹 + 前端动作（自动跳到成绩页）
```

## 8. 我还没做好的地方（老师问"局限"时可以直接说）

1. 多轮记忆存在进程内存里（MemorySaver），重启即丢，多实例部署会串；生产应换 Redis/Postgres checkpointer。
2. 离线规则引擎只覆盖常见说法，复杂问法还是得靠模型。
3. 权限粒度偏粗：教师能查所有班级成绩，理想状态应按"本人授课班级"过滤。
4. 没上数据库迁移工具（现在靠 create_all），表结构演进要靠 Alembic。
5. 前端是单文件原生 JS，工程化（构建、路由、单测）还没做。

## 9. 老师可能追问的问题与我的回答

**Q1：为什么不用 LangChain 现成的 AgentExecutor / Function Calling？**
A：一是各家协议不一致（3.1 已踩过），二是这套流程我要精确控制"最多两轮、失败如何兜底、哪些数据能进模型"，
状态图比黑盒 Agent 更好调试；LangSmith 里能一眼看到每一步输入输出。

**Q2：没配 Key 也能跑，是不是"假 AI"？**
A：不是替代，是兜底。有 Key 时走真模型（线上就是这个模式）；无 Key/超时/报错时才降到规则引擎，
保证演示和自动化测试不被网络卡死。两套入口是同一个 plan/answer 接口。

**Q3：RAG 用 TF-IDF，算不算糊弄？**
A：接口和向量检索完全一致（ensure_loaded/search），只是默认用本地相似度保证零依赖秒启动；
配上独立 embedding Key 就是真向量检索（12 秒超时，失败自动回退）。

**Q4：异步和多线程的区别？**
A：协程是一个线程内切换任务，适合 IO 等待；线程池是真并行，用来卸载阻塞调用。
这个项目里 99% 是协程，只有 Excel 解析走了 to_thread。

**Q5：状态图比链式调用强在哪？**
A：链式只能一条路走到底；状态图能分支（有工具/没工具）、能多轮（executor 回到 planner）、能记状态（多轮记忆），
出错还能单独重跑某个节点。

**Q6：大模型胡说怎么办？**
A：三道闸：工具只返回数据库真实数据；提示词要求"只使用工具结果、不许编造"；
回答里数据不对可以在 LangSmith 里回放当次调用定位。

**Q7：并发上来会怎样？**
A：压测过：本机 30 并发 150 次请求 0 失败。服务是单进程异步 + 连接池（pool_size 10 / max_overflow 20），
再往上加需要 uvicorn 多 worker + Nginx。带宽是当前瓶颈（1Mbps），不是 CPU。

**Q8：密钥和数据安全怎么管的？**
A：密钥只在 .env（已 gitignore，权限 600），代码里没有硬编码；登录用 HMAC 令牌 + PBKDF2 密码；
教师上传限 5MB 且只收 .xlsx；登录 5 分钟 8 次失败即锁。还没做的是 HTTPS 与按班级的数据权限。

## 11. 一句话答辩稿

"我的系统里，LangChain 负责把大模型接进来（可换厂商、可降级），LangGraph 负责把不确定的智能行为装进可控的流程
（规划-执行-作答，带多轮记忆），Python 异步负责让数据库、文件和模型调用不互相堵住。

状态与连接不能混（会话走 config 不进 state）、以及异步的 await 语义（写错位置会报 coroutine 没有该方法）。
最终用 60 项自动化用例、PostgreSQL 复测和 150 次并发压测证明它能跑。"
