## 二、一条请求走完全程（以「学生查成绩」为例）

### 第 0 层：启动时发生了什么

app/main.py 的 lifespan 是整个应用的"开机流程"：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    settings.ensure_dirs()      # 1. 建 data/exports、knowledge 等目录
    settings.apply_langsmith_env()
    await init_db()             # 2. create_all 建表（幂等）
    await seed_if_empty()       # 3. 库为空才灌种子数据
    asyncio.create_task(_warm_kb())   # 4. 知识库后台预热，不阻塞启动
    yield
```

这里有两个设计点值得记住：
- `await init_db()` 必须是同步等待（表都没建好，别接请求）；
- 知识库预热**不能**等（曾经因为等它 2 分钟，端口迟迟不监听，浏览器报 ERC_CONNECTION_REFUSED）。

### 第 1 层：路由 → 鉴权 → 取数据

```python
# app/api/student.py
@router.get("/grades")
async def grades(semester: str = Query(default=""),
                 principal: dict = Depends(require_role("student")),   # ← 鉴权在这
                 db: AsyncSession = Depends(get_db)):                  # ← 会话在这
    stu = await _me(principal, db)                                     # 用令牌里的学号查本人
    stmt = select(Grade).where(Grade.student_id == stu.id)
    if semester:
        stmt = stmt.where(Grade.semester == semester)
    rows = (await db.execute(stmt)).scalars().all()
    credits = round(sum(g.credit for g in rows), 1)
    gpa = round(sum(grade_point(g.score) * g.credit for g in rows) / credits, 2) if credits else 0
    return {"items": [...], "summary": {...}}
```

三个必须看懂的点：
1. `Depends(require_role("student"))` 不只是"要登录"，而是"必须是学生"，越权直接 403；
2. `principal` 里的 username 是**令牌里的学号**，不是请求参数——所以学生改 URL 也查不到别人的；
3. `db.execute` 前必须有 `await`，这是异步 ORM 的硬要求（忘了就报 coroutine 没有该方法）。

### 第 2 层：会话与事务从哪来

```python
# app/db/session.py
engine = create_async_engine(settings.database_url, **kwargs)
SessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db():
    async with SessionLocal() as session:
        try:
            yield session
            await session.commit()      # 正常结束自动提交
        except Exception:
            await session.rollback()    # 出错自动回滚
            raise
```

所以业务代码里几乎不写 commit，只写 `await db.flush()`（拿到自增 id）；提交交给这一层统一处理。

## 三、核心机制精读

### 3.1 认证：令牌里到底装了什么

```python
# app/security.py
def create_token(role: str, uid: int, username: str) -> str:
    payload = {"role": role, "uid": uid, "username": username,
               "exp": int(time.time()) + settings.token_expire_minutes * 60}
    body = _b64e(json.dumps(payload, separators=(",", ":")).encode())
    sign = hmac.new(settings.secret_key.encode(), body.encode(), hashlib.sha256).hexdigest()[:32]
    return body + "." + sign            # base64url(payload).签名

def require_role(role: str):
    async def _checker(principal: dict = Depends(get_principal)) -> dict:
        if principal.get("role") != role:
            raise HTTPException(status_code=403, detail="当前身份无权访问该接口")
        return principal
    return _checker
```

没有用 pyjwt，是为了少一个依赖，但 JWT 的三个要素（payload、签名、过期）都在。
密码是 PBKDF2 + 每用户随机盐（12 万次迭代），库里不存明文。

### 3.2 数据模型：13 张表怎么分工

| 层 | 表 | 关键设计 |
| --- | --- | --- |
| 人 | students / teachers / admins | 学号、工号唯一索引；密码哈希；学生带 class_id |
| 组织 | classes | 班级名唯一，带辅导员 |
| 教学 | courses / timetable | 课程按学期；课表用 weekday + 起止节次 + 教室描述一个时段 |
| 结果 | grades | `UniqueConstraint(student_id, course_code, semester)` 防重复录入 |
| 互动 | notifications / messages | 通知有 target_class_id（空=全校）；消息带未读标记 |
| 事务 | exam_appointments / enrollments / schedule_changes / applications | 预约、选课、调课申请、通用报名（用 app_type 区分 8 类申请） |
| 运营 | proctors / textbooks / meetings / recovery_requests | 监考、教材、会议、账号找回 |

设计上刻意的取舍：
- **通用申请表单**：不建 8 张表，用 `applications + app_type`，加一种申请不用改表结构；
- **成绩唯一约束**：教师重复上传同一门课的成绩时，代码里是"存在则更新"，数据库再兜一层唯一约束。

### 3.3 教师上传成绩：同步库怎么放进异步服务


### 3.4 LangGraph：四个节点就是四句话

```python
# app/ai/graph.py —— 节选，完整代码 178 行
class AgentState(TypedDict, total=False):
    role: str; question: str; messages: list; plan: list
    tool_results: list; ui_actions: list; answer: str; model: str; trace: list

async def intake_node(state, config):        # ① 把问题写进历史（保留最近 12 条）
    messages = list(state.get("messages") or []) + [{"role": "user", "content": state["question"]}]
    return {"messages": messages[-12:]}

async def planner_node(state, config):       # ② 让模型决定调哪个工具
    history = "\n".join(m["role"] + ": " + str(m["content"])[:120]
                        for m in (state.get("messages") or [])[-6:-1])
    prev = state.get("tool_results") or []   # 把上一轮结果摘要给规划器，支持「那英语呢」
    if prev:
        history += "\n[上一轮工具结果] " + "；".join(
            r["tool"] + " -> " + str(r.get("message", ""))[:60] for r in prev[-2:])
    calls = await get_llm(state["role"]).plan(state["question"], tools_for(state["role"]), history)
    return {"plan": calls, "trace": [...], "model": ...}

async def executor_node(state, config):      # ③ 真正查/写数据库
    ctx = config["configurable"]["ctx"]      # 会话与登录态从 config 拿，不进 state
    for call in state.get("plan") or []:
        try:
            res = await tools[call["tool"]]["fn"](ctx, **call.get("args", {}))
        except Exception as exc:             # 单个工具失败不炸图
            res = {"ok": False, "message": "执行 " + call["tool"] + " 时出错：" + str(exc)[:120]}
        results.append({...})
        await ctx["db"].flush()
    return {"tool_results": results}

async def responder_node(state, config):     # ④ 把结果润色成人话
    answer = await get_llm(state["role"]).answer(state["question"], state.get("tool_results") or [], SYSTEM_PROMPTS[state["role"]])
    return {"answer": answer, "messages": ..., "ui_actions": ...}

graph = StateGraph(AgentState)
graph.add_node("intake", intake_node)
graph.add_node("planner", planner_node)
graph.add_node("executor", executor_node)
graph.add_node("responder", responder_node)
graph.set_entry_point("intake")
graph.add_edge("intake", "planner")
graph.add_conditional_edges("planner", lambda s: "executor" if s.get("plan") else "responder",
                            {"executor": "executor", "responder": "responder"})
graph.add_edge("executor", "responder")
graph.add_edge("responder", END)
agent_graph = graph.compile(checkpointer=MemorySaver())     # ← 多轮记忆在这
```

四个一定要讲清楚的细节：
1. **state 只放纯数据**。数据库会话放进去会破坏 checkpointer（不可序列化），所以走 `config["configurable"]`。
2. **thread_id 决定记忆边界**：`角色:账号:会话ID`，少了账号就会串话。
3. **条件边**让"没工具"的问题少绕一圈。
4. `executor` 里的 try/except 是**故意**的：模型可能编参数，一个工具报错不该让用户整段对话失败。

### 3.5 工具层：一个约定，19+14 个能力

所有工具都是同一个形状，这让"加功能"变成填空题：

```python
# app/ai/tools_student.py
async def _query_grades(ctx: dict, course_name: str = "") -> dict:
    stu = await _student(ctx)                       # ctx 里有 db、学号、班级
    rows = (await ctx["db"].execute(select(Grade).where(...))).scalars().all()
    ...
    return {"ok": True, "data": [...], "message": "查到你的成绩：...", "ui": [...]}

STUDENT_TOOLS = {
    "query_grades": {"desc": "查询成绩（可指定课程）", "params": {"course_name": "课程名"}, "fn": _query_grades},

```

返回值的四个字段是契约：`ok` 成没成、`data` 给前端、`message` 给人和离线模式用、`ui` 让前端自动跳页。
注册表里的 `desc/params` 会被 `llm.py` 渲染成提示词里的工具清单——**改描述就等于改模型行为**。

关键取舍：**默认离线**，因为向量接口不一定存在（DeepSeek 就没有 /embeddings），而且要保证秒启动。

### 3.7 异步细节：三处容易写错的地方

| 错误写法 | 后果 | 正确写法 |
| --- | --- | --- |
| `db.execute(...)` 忘 await | 拿到 coroutine，后续报 `'coroutine' object has no attribute ...` | `await db.execute(...)` |
| `await db.execute(...).order_by()` | await 绑到了错误的对象上，同样报 coroutine 错误 | 把 `order_by` 放进 `select` 里 |
| 在 async 函数里直接调 `load_workbook` | 阻塞事件循环，所有人都在等 | `await asyncio.to_thread(...)` |

## 六、给你自己加功能的三个套路

**加一个普通接口**：`api/xxx.py` 写 `@router.get` + `Depends(require_role(...))` + `Depends(get_db)` → `main.py` 注册 router → 前端加菜单项（`registry.py` 标 ready）。

**加一个 AI 工具**：`tools_student.py` 写 `async def _foo(ctx, ...) -> dict` → 在 `STUDENT_TOOLS` 加一行（desc 写清楚，模型靠它选工具）→ 若希望离线也能用，在 `mock_llm.py` 加一条关键词规则。

**加一张表**：`models.py` 定义类（带 `Mapped[...]`）→ 启动自动 `create_all` 建表 → 若线上已有数据，写一个 `scripts/seed_extra.py` 式的补数脚本。

---

**最后一句**：这份后端的复杂度不在"代码量"，而在三件事的边界——
**谁能看什么（鉴权）、哪里会阻塞（异步）、模型出错谁兜底（降级）**。
把这三条讲清楚，比逐行念代码更能体现你真的理解了系统。
